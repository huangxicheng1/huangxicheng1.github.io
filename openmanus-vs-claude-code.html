OpenManus 和 Claude Code：两种 Agent 骨架的差别

同样是「想一步、做一步、再想一步」，为什么一个是 4 个文件，一个是几十兆的打包产物
🎯 一句话：你贴的这套结构（BaseAgent → ReActAgent → ToolCallAgent → Manus）回答的是「agent 怎么跑起来」；Claude Code 回答的是「agent 跑起来之后，怎么不跑崩」。
所以真正的差别不在继承层级，而在 主干上是成功路径，还是失败路径——OpenManus 的主循环只写了一条「继续」，Claude Code 的主循环写了四条出口，其中三条是「出错了但继续」。

7Claude Code 一次工具调用要过的关卡数

① 打个比方：单机游戏 vs 网游服务端

你贴的这套代码，像一款单机游戏：主循环六十行，能跑就行。卡住了怎么办？重启。存档就一个文件，坏了重来。

Claude Code 像网游服务端：主循环也就那么几十行，但周边堆了断线重连、反外挂、防刷、限流、存档回滚、操作审计。因为它的用户是几十万人，一次崩溃就是一次事故，没人会帮你重启。

这个比方能推下去，是因为两者的「难点」根本不在同一层：

· 单机的难点是「游戏好不好玩」＝ prompt 写得怎么样、工具够不够用

· 网游的难点是「玩家掉线了怎么算、刷金币怎么封、服务器满了怎么办」＝ 失败路径怎么收场

所以这一页的判断是：OpenManus 的类在管「怎么想、怎么动」；Claude Code 的循环在管「动了之后出岔子怎么办」。两者都对，只是回答的不是同一个问题。

② 骨架对比：一条继承链 vs 一台状态机

先看你贴的这套。它是标准的模板方法模式：父类定好骨架，子类只填一个洞。

BaseAgent —— 状态机 + run() 主循环 + stuck 检测
ReActAgent —— step() = think() + act()（两个都留空）
ToolCallAgent —— 把 think/act 用 function calling 填上
Manus —— 只做一件事：指定默认工具集 + 接 MCP
每一层只加一件事，加完就停。想加能力 = 再往下继承一层。

再看 Claude Code。它没有这条链。没有 BaseAgent，没有 think()/act() 两个抽象方法，也没有靠继承叠能力。它的形状是「一个循环 + 一圈横向关卡」：

Iteration主循环入口
──▶
APICall唯一耗时点
──▶
ToolExec执行工具
↩
横向zod 校验PreToolUse hook权限引擎沙箱PostToolUse hook
纵向TokenBudgetReactiveCompactMaxOutputRecoveryStopHook
主干极短，真正的代码量全在这些「关卡」上。加能力不靠继承，靠配置和挂载。
一句话说清这个差别：继承是「编译期确定的能力组合」——你能列出这个 agent 会做哪几件事；关卡是「运行期逐次判断的约束」——你列不出它不会做什么，只能保证每一步都被拦一道。

③ 主循环：都是几十行，但重心完全相反

OpenManus 的 run() 骨架，剥掉日志之后大概就是：

step()think + act
──▶
追加消息记忆列表

只有一条继续路径：一切正常，就再转一圈。异常怎么办？外层 try/except 抓住，状态置 ERROR，整个任务结束。

Claude Code 的循环长这样，注意出口数量：

Iteration转一圈
──▶
APICall问模型
──▶
四个出口见下
出口 1有工具调用 → ToolExec → 回 Iteration（正常路径）
出口 2模型说完了（end_turn）→ Completed → 查预算 → 过 StopHook → 结束
出口 3输出被截断 → MaxOutputRecovery（注入一条「接着写」）→ 回 Iteration
出口 4上下文太长 → ReactiveCompact（压缩历史）→ 排空队列 → 回 Iteration
四个出口，两个是「出错了但继续」。这就是全部差别的来源。
OpenManus 的假设
一次调用失败 = 这个任务大概率做不成了，交给用户重来。
Claude Code 的假设
一次调用失败 = 这一步不行，换个写法再试，任务本身还有救。
代价（OpenManus 侧）
便宜、好读、好改。做原型、教学、单机工具都够用。
代价（Claude Code 侧）
状态机节点数远超业务逻辑，新人读起来像在读错误码大全。

④ 出岔子了：两种完全不同的「止损」

这是两套代码最有意思的对照。同样是「模型卡住不动了」，两边的做法几乎相反。

OpenManus：检测「行为」

把最近几条消息拿出来比，内容一模一样就判定卡住（is_stuck()），然后往上下文里注入一句「你重复了，换个策略」，同时把判定阈值调高（handle_stuck_state()）。

这是启发式：聪明，但会误判——正常的重试也会被判成卡住。

Claude Code：检测「资源」

没有重复检测这一说。它靠四道硬闸：恢复次数上限（截断重试最多 3 次）、token 预算、StopHook（模型想收工，外部可以否掉）、用户中断。

这是确定性：笨，但绝不漏——钱花光了就是花光了。

为什么 Claude Code 敢不做 stuck 检测？因为它有 token 预算和人的中断当兜底。当你有硬止损的时候，软检测就是冗余——而软检测本身还会误伤正常重试。反过来，OpenManus 没有预算概念（本地跑，不按 token 计费），所以它必须靠「猜模型是不是卡了」来兜。

再看第二个差异，也是我认为最值钱的一条：失败的时候，停在哪一层。

OpenManus：run() —— 整个任务 ✓ 继续？
step() —— 一轮
think / act —— 一次调用
这里抛异常 ✗ → 一路冒到 run()，state = ERROR，整个任务结束
失败粒度 = 任务。一次工具调不通，整个活儿就废了。
Claude Code：会话 —— 继续 ✓
Iteration —— 这一轮
一次 tool call —— 被 hook 拒 / 被沙箱拒 / 工具失败
只终止这一次调用 ✗，把拒绝原因回喂模型，循环继续
失败粒度 = 调用。拦下这一下，下一轮换个姿势接着干。

这一条能解释 Claude Code 里那两个看起来很奇怪的设计：为什么 HookStopped 是个「终止状态」，但会话没结束？因为它终止的只是这一次工具调用；模型收到「你被拒了，原因是 X」之后，下一轮会自己换方案。终止的是调用，不是任务。

⑤ 两种扩展观：改代码 vs 改配置

假设你现在要加一条规则：不许改 .env。两边分别怎么做？

❌ 继承式：要动代码

新建 SafeToolCallAgent(ToolCallAgent)，覆写 act()，在执行前检查工具参数里的路径。然后 Manus 改成继承它。

问题是：改一次策略 = 一次发版。而且策略越多，子类越多，继承链越长——最后你会得到一个 7 层深的 XXXToolCallAgent。

✅ 关卡式：只动配置

写一行 "deny": ["Read(./.env)"]，或者扔一个 hook 脚本进去。主程序一行不改，热生效，还能按项目分别配。

代价是你没法靠读代码知道 agent 会做什么——必须同时读配置、hook、插件。调试成本从开发侧挪到了运维侧。

这个取舍背后是一条更硬的道理：agent 的失败模式是无穷的，没法用继承预先枚举。你写代码的时候想不到「模型会用 python -c 绕开 curl 的限制」，但你可以挂一个 hook 说「所有出网请求先过我这」。继承只能表达「你会什么」，关卡才能表达「你不许什么」。

⑦ 三个反直觉的地方

反直觉一
大家以为 agent 难在「推理、prompt、模型能力」。实际看下来，Claude Code 状态机里 八成节点在处理「输出被截断」「上下文满了」「模型说完了但其实没完」，跟智能一点关系都没有。难的是收场，不是思考。
反直觉二
大家以为「继承链深 = 设计差」。但在 OpenManus 这个体量下，4 层继承是最省读者脑力的写法。层数本身不是罪，超出规模才是。
反直觉三
大家以为 Claude Code 不做 stuck 检测是「漏了」。恰恰相反：它有预算和人的中断，软检测就是冗余，还会误伤正常重试。有硬止损就不需要软检测。
常见误解
「读 Claude Code 源码就能学会」——它是打包混淆的单文件，社区做的是行为逆向。所以任何「源码级对比」最多到「可观测行为」这一层，函数名、变量名基本都是推测。
合上页面前，试着答一下
  1. 为什么 Claude Code 不用继承链来叠能力？它的「关卡」解决了继承做不到的什么事？
  2. 一次工具调用失败，在两边分别停在哪一层？这个差别带来什么实际后果？
  3. OpenManus 的重复检测和 Claude Code 的预算上限，各自在防什么？为什么后者敢不做前者？
OpenManus 决定「怎么想、怎么动」；Claude Code 决定「动了之后出岔子怎么收场」；你的规模决定该用哪一种
跳出细节看：OpenManus 是「agent 的最小完备定义」——把 think / act / loop 三件事讲清楚了，几百行就能读完。Claude Code 是「agent 的生产化封装」——它默认模型一定会犯错、上下文一定会满、用户一定会点错，然后围着这些「一定」建了一圈防线。前者教你 agent 是什么，后者教你 agent 怎么活下来。面试里能把这两句话分开说，比背多少实现细节都有用。
